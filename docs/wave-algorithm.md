# Волна: как это работает

Код: `js/wave.js` (чистые функции, все константы в объекте `WAVE`), `js/similar.js` (сеть). Тесты: `node --test tests/wave.test.mjs`.

## 1. Профиль вкуса: `buildTaste`

Сигнал одного прослушивания `s`:
- дослушал (`playedFraction ≥ COMPLETE_FRACTION`): `+1`;
- ушёл раньше `SKIP_SECONDS` (секунды — `played` или `playedFraction × длительность`; если длительность неизвестна, доля меньше `SKIP_FRACTION`): `SKIP_SIGNAL`;
- иначе: `s = playedFraction`.

Вес артиста складывается с затуханием по времени, `decay(t, T) = 2^(−возраст/T)`:

```
вес = Σ s·decay(HALF_LIFE_DAYS)
    + Σ LIKE_SIGNAL·decay(LIKE_HALF_LIFE_DAYS)
    + Σ DISMISS_SIGNAL·decay(DISMISS_HALF_LIFE_DAYS)
    + априор·log2(1 + треков в библиотеке)
близость = вес / (|вес| + AFFINITY_K)        // от −1 до 1, один артист не забивает всех
```

- Если у трека несколько артистов, каждому достаётся `1/√n`. «A & B» делится, только если A или B встречаются и сами по себе; иначе это одна группа.
- Лайк или «не моё» с полем `seed` дополнительно двигает вес семени на `SEED_FEEDBACK`.
- `ARTIST_BAN_DISMISSALS` раз «не моё» или «не моё» без названия трека: артист в бане.

**Холодный старт.** `априор = LIB_PRIOR·(LIB_PRIOR_FLOOR + (1 − FLOOR)·холод)`, `холод = max(0, 1 − прослушиваний/COLD_LISTENS)`. Пока прослушиваний мало, вкус определяет состав библиотеки: чем больше треков артиста, тем выше он в волне и чаще становится семенем.

## 2. Волна из своей библиотеки: `nextWave`

```
база    = max(0.05, 1 + TASTE_ARTIST·близость_артиста + TASTE_TRACK·близость_трека)
свежесть = 1 − e^(−часов_с_прослушивания / FRESH_TAU_HOURS)   // новый трек: 1 + UNPLAYED_BONUS
вероятность ∝ база² · свежесть
```

- С вероятностью `EXPLORE` (`EXPLORE_COLD` при холодном старте) очередной трек выбирается без учёта вкуса, чтобы не крутить одни и те же десять песен. Явно нелюбимых артистов (близость ниже −0,3) разведка не берёт.
- Ограничения: нет последних `min(RECENT_TRACKS, RECENT_SHARE·размер)` треков, между треками одного артиста минимум `ARTIST_GAP`, в одной пачке не больше `MAX_PER_ARTIST` от артиста.
- Если ограничениям ничего не отвечает (маленькая библиотека), они ослабляются, но волна не обрывается. Забаненные не возвращаются никогда.

## 3. Новая музыка: `fetchSuggestions`

1. **Семена** (`pickSeeds`): случайный выбор артистов с вероятностью ∝ близость². Поэтому разные обновления дают разные подборки.
2. **Похожие артисты:** MusicBrainz (имя в идентификатор, в том числе по псевдонимам: Zemfira находит Земфиру), затем ListenBrainz. Если там пусто, Last.fm при наличии ключа. Если и там пусто, соавторы и новые треки самого артиста из iTunes.
3. **Сводка кандидатов** (`mergeSimilar`): `сумма = Σ близость_семени · сходство`, сходство нормируется на лучшего в списке. Кандидаты берутся по кругу между семенами. Соавторы весят `COLLAB_SIM` от обычного сходства.
4. **Песни:** iTunes, сначала русский магазин (там имена кириллицей), при пустом ответе американский.
5. **Ранжирование** (`rankCandidates`):

```
балл = W_SIM·сходство + W_SEED·близость_семени + W_NOVEL·новизна + W_POP·популярность
     + W_FEEDBACK·близость_кандидата − W_SEEN·показов_без_отклика − W_JUNK·(караоке и т. п.)
     + W_JITTER·случай
```

`новизна` = 1 для незнакомого артиста, `KNOWN_NOVELTY` для знакомого. Убирается то, что уже есть в библиотеке или отвергнуто. Сравнение идёт по `normKey`: без регистра, ё = е, без скобок и feat., кириллица в транслите (Кино = Kino). Артист с близостью не выше `ARTIST_DROP` исключается. Лимиты: `maxPerArtist`, а на семя — доля `MAX_SHARE_PER_SEED`.

## Константы

| Константа | Значение | Что меняет |
|---|---|---|
| `HALF_LIFE_DAYS` | 30 | как быстро забываются прослушивания |
| `LIKE_HALF_LIFE_DAYS` / `DISMISS_HALF_LIFE_DAYS` | 120 / 180 | то же для лайков и «не моё» |
| `COMPLETE_FRACTION` | 0,8 | с какой доли трек считается дослушанным |
| `SKIP_SECONDS` / `SKIP_FRACTION` | 30 / 0,15 | порог пропуска |
| `SKIP_SIGNAL` / `LIKE_SIGNAL` / `DISMISS_SIGNAL` | −0,5 / 3 / −4 | сила сигналов |
| `SEED_FEEDBACK` | 0,25 | влияние отклика на семя |
| `ARTIST_BAN_DISMISSALS` | 3 | сколько «не моё» до бана артиста |
| `AFFINITY_K` | 2 | насыщение близости: больше — плавнее |
| `COLD_LISTENS` | 15 | до скольких прослушиваний старт холодный |
| `LIB_PRIOR` / `LIB_PRIOR_FLOOR` | 0,3 / 0,2 | вес состава библиотеки |
| `TASTE_ARTIST` / `TASTE_TRACK` | 1,5 / 1 | сила вкуса в волне |
| `FRESH_TAU_HOURS` | 48 | как быстро трек снова становится свежим |
| `UNPLAYED_BONUS` | 0,25 | бонус ни разу не игранным |
| `RECENT_TRACKS` / `RECENT_SHARE` | 50 / 0,5 | запрет на недавние |
| `ARTIST_GAP` / `MAX_PER_ARTIST` | 3 / 2 | разнообразие артистов |
| `EXPLORE` / `EXPLORE_COLD` | 0,15 / 0,35 | доля разведки |
| `W_SIM`, `W_SEED`, `W_NOVEL`, `W_POP` | 1, 0,6, 0,5, 0,25 | веса балла новых треков |
| `W_FEEDBACK`, `W_SEEN`, `W_JUNK`, `W_JITTER` | 1, 0,3, 1, 0,15 | то же |
| `KNOWN_NOVELTY` | 0,3 | новизна знакомого артиста |
| `ARTIST_DROP` | −0,5 | ниже этой близости артист не предлагается |
| `MAX_SHARE_PER_SEED` | 0,4 | доля выдачи от одного семени |
| `COLLAB_SIM` | 0,7 | вес соавторов |

Сеть (`js/similar.js`): паузы между запросами `GAPS` (MusicBrainz 1,1 с, iTunes 3,2 с), срок кэша `TTL` (идентификаторы 90 дней, похожие 30, песни 14; пустые ответы короче, сбои не кэшируются), бюджет на вызов: `itunesBudget` = 10 запросов, `budgetMs` = 90 с.

## Какой трек после какого

К весу кандидата добавляется множитель `flowScore(предыдущий, кандидат)`, не меньше `FLOW_MIN`:
- **Жанр** из iTunes: совпал ×1,6, другой ×0,75.
- **Эпоха:** разница до 5 лет ×1,15, больше 20 лет ×0,85.
- **Темп** считается по звуку: близкий или вдвое отличающийся ×1,25, разница больше 25% ×0,85.
- **Громкость** считается по звуку: до 3 дБ ×1,1, от 10 дБ ×0,85.
- **Привычки:** если после артиста A ты дослушиваешь артиста B, пара усиливается, если пропускаешь — ослабляется.

Чего нет в данных, то ничего не меняет. На компьютере темп считается заранее для скачанных треков, на телефоне — по мере прослушивания. То же работает в «Слушать вперемешку».
